# Как изучать Apache Iceberg

Цель маршрута — научиться создавать таблицы, понимать их версии и метаданные, менять схему и партиционирование, а затем обслуживать таблицы. Это авторский учебный материал на основе документации Iceberg **1.12.0**. Полные параметры и ограничения ищите в [справочнике](../reference/README.md) и [карте документации](../MOC.md).

Нужны базовый SQL (`SELECT`, `JOIN`, `GROUP BY`, `INSERT`) и понимание файлов и каталогов. Java и Flink для первого прохода не нужны. Для практики используется Spark: его SQL позволяет увидеть основные операции Iceberg в одном окружении. Возможности другого движка проверяйте в его документации; синтаксис Spark не переносится автоматически в Trino.

## Лабораторная

[Окружение и пошаговый сценарий](../labs/README.md) содержит конкретные версии, команды, SQL и ожидаемые результаты. Один запуск проходит шаги 2–5 и автоматически проверяет результаты. Затем повторите операции вручную в интерактивном Spark SQL.

Не требуется последовательно читать все AWS-, Flink-, Hive- и Java-разделы. После общего маршрута выберите свою ветку:

- **SQL и пакетная загрузка:** Spark DDL → Queries → Writes → Procedures.
- **Потоковая загрузка:** Flink → Connector → Queries/Writes → Configuration → Maintenance. Отдельно разберите checkpoints и ограничения incremental reading.
- **Общее хранилище для нескольких движков:** Catalog properties → выбранный каталог → File I/O → документация каждого движка.
- **Разработка интеграций:** Java API quickstart → API → File I/O → REST protocol.
- **Миграция:** Table migration → Hive или Delta Lake migration; сначала проверить миграцию на копии и сопоставить данные.

## Самопроверка после маршрута

1. Почему каталог, Iceberg и Parquet — разные части системы?
2. Как читатель видит согласованную таблицу, пока writer готовит новые файлы?
3. Почему переименование колонки не требует перезаписи всех файлов?
4. Почему смена partition spec не переразбивает старые файлы?
5. Чем отличаются rollback, expiration snapshots и удаление orphan files?
6. Почему уменьшение числа файлов не обязано ускорить любой запрос?
7. Какие операции необходимо отдельно проверить для выбранного движка?

Ответы: [модель таблицы](01-table-model.md), [snapshots](02-snapshots.md), [обслуживание](03-maintenance.md), [эксплуатация](04-catalogs-and-operation.md).

Маршрут завершён, когда вы можете объяснить изменения в metadata tables после каждой операции и самостоятельно выполнить лабораторную с другой схемой данных, сохранив проверки результата.
