# Документация

**Apache Iceberg — открытый табличный формат для очень больших аналитических наборов данных.** Iceberg добавляет табличную модель в вычислительные движки, включая Spark, Trino, PrestoDB, Flink, Hive и Impala, используя высокопроизводительный табличный формат, который для пользователя ведёт себя как SQL-таблица.

### Пользовательский опыт

Iceberg устраняет неприятные неожиданности. Эволюция схемы работает предсказуемо и не может случайно «вернуть» ранее удалённые данные. Пользователю не требуется знать физическую схему партиционирования, чтобы получать быстрые запросы.

- [[evolution#Эволюция схемы|Эволюция схемы]] поддерживает добавление, удаление, изменение и переименование полей без побочных эффектов.
- [[partitioning|Скрытое партиционирование]] предотвращает ошибки, которые могут незаметно приводить к неправильным результатам или крайне медленным запросам.
- [[evolution#Эволюция партиционирования|Эволюция схемы партиционирования]] позволяет менять физическое размещение таблицы по мере роста объёма данных или изменения профиля запросов.
- [[spark-queries|Time travel]] позволяет воспроизводимо выполнять запросы к точно определённому snapshot таблицы и анализировать исторические изменения.
- Rollback версии позволяет быстро исправить проблему, вернув таблицу к корректному состоянию.

### Надёжность и производительность

Iceberg создавался для очень больших таблиц. Он используется в production, где одна таблица может содержать десятки петабайт данных; при этом такие таблицы можно планировать для чтения без необходимости запускать распределённый SQL-движок только ради поиска файлов.

- [[performance#Планирование сканирования|Планирование сканирования выполняется быстро]] — для чтения таблицы и поиска нужных файлов не требуется распределённый SQL-движок.
- [[performance#Фильтрация данных|Расширенная фильтрация]] — data files отбрасываются по партиционной и поколоночной статистике из метаданных таблицы.

Iceberg проектировался для решения проблем корректности в облачных объектных хранилищах с eventual consistency.

- [[reliability|Работает с любым облачным объектным хранилищем]] и при использовании HDFS уменьшает нагрузку на NameNode, избегая listing и rename как основы определения состояния таблицы.
- [[reliability|Serializable isolation]] — изменения таблицы атомарны, а читатели никогда не видят частично записанное или незакоммиченное состояние.
- [[reliability#Конкурентные операции записи|Несколько конкурентных writers]] используют optimistic concurrency и повторные попытки, благодаря чему совместимые обновления могут успешно завершаться даже при конфликтах записи.

### Открытый стандарт

Iceberg спроектирован и развивается как открытый стандарт сообщества. Формальная спецификация обеспечивает совместимость между языками и реализациями.
