# Версии данных и commit

Snapshot описывает состояние данных таблицы в определённой версии. Изменение данных создаёт новый snapshot, который может переиспользовать файлы предыдущих версий. Это не полная физическая копия таблицы при каждом INSERT.

Writer сначала готовит файлы и новые метаданные, затем пытается опубликовать изменение через механизм каталога. Читатель продолжает использовать согласованный snapshot. При конфликте writers возможны повторная попытка или ошибка валидации — в зависимости от операции и изменившихся данных.

## Три разных действия

| Действие | Результат | Что проверить |
| --- | --- | --- |
| Time travel | Читает выбранный snapshot, не меняя текущий | Snapshot ещё существует, файлы доступны |
| Rollback | Меняет текущий snapshot на допустимого предка | Какие записи перестанут быть текущими; результат последующих загрузок |
| Expiration | Удаляет выбранные старые snapshots и может удалить больше не нужные файлы | Retention, ссылки branches/tags и потребности читателей |

Snapshot ID — технический идентификатор, а не порядковый номер. В лабораторной он считывается из результата записи; не подставляйте ID из чужого запуска.

```sql
SELECT snapshot_id, parent_id, operation
FROM lab.training.events.snapshots;

SELECT made_current_at, snapshot_id, is_current_ancestor
FROM lab.training.events.history;
```

`snapshots` показывает сохранённые snapshots, `history` — историю назначения текущего snapshot. После rollback эти представления помогают отличить существующую версию от текущей линии истории.

## Изменение строк

`MERGE INTO` сопоставляет источник с таблицей и применяет заданные UPDATE/INSERT/DELETE. Повторная загрузка не становится идемпотентной автоматически: нужны корректный ключ и определённая обработка повторов в источнике. Iceberg не обеспечивает уникальность `id` только потому, что колонка называется ключом.

Copy-on-write переписывает затронутые data files. Merge-on-read может записывать delete files и новые data files; чтение должно учитывать удаления. Поддержка режимов зависит от операции, версии формата и движка. В учебной таблице явно используется format v2 и copy-on-write, чтобы первый эксперимент был проще.

Изменение схемы — отдельное изменение метаданных. Rollback данных не следует считать универсальной отменой DDL: после лабораторного rollback добавленная колонка остаётся в актуальной схеме. Это проверяется отдельно.

## Branches и tags

Tag фиксирует ссылку на snapshot. Branch поддерживает отдельную линию изменений данных. Их retention влияет на то, какие snapshots и файлы можно удалить. Branch не является полностью независимой копией схемы таблицы: схема развивается на уровне таблицы.

В первом проходе достаточно понимать назначение ссылок. Затем выполните примеры [ветвления и тегов](../docs/branching.md), если нужны аудит загрузки, публикация после проверки или сохранение контрольной версии.

## Самопроверка

**Задание:** после ошибочного MERGE выполнен rollback. Можно ли сразу удалить все файлы, созданные MERGE?

**Ответ:** нельзя определять это только по текущему SELECT. Сохранённый snapshot или другая ссылка могут ещё использовать файлы. Обслуживание должно учитывать все сохраняемые версии. Физическое удаление вручную обходит эти гарантии.
