## 2. Полнота перевода

Корневая политика репозитория определяет `translated` как **полный перевод**.

Выборочная сверка показала, что ряд существующих страниц является качественным конспектом, но не полным переводом source document.

Размер файла сам по себе не является доказательством неполноты, поскольку HTML markup и русский текст имеют разный объём. Поэтому для выборки дополнительно сравнивалась структура и фактическое содержание.

### `docs/comment.md`

Upstream:

- `_content/doc/comment.md`;
- размер upstream-файла: 37 332 bytes.

Локальная версия:

- `docs/comment.md`;
- размер: 12 551 bytes.

Ручная сверка секции `Commands` показала, что upstream содержит большой исходный пример документации `gofmt` и последующее подробное объяснение, тогда как локальная версия заменяет этот материал коротким списком и несколькими предложениями.

Вывод: это сокращённая адаптация, а не полный перевод.

### `docs/tutorial/create-module.md`

Upstream:

- `_content/doc/tutorial/create-module.html`;
- 8 003 bytes.

Локальная версия:

- 3 077 bytes.

В upstream присутствуют отдельные prerequisites, пошаговые инструкции, дополнительные пояснения module lifecycle и подробное описание каждого действия. Существенная часть prose в локальной версии сокращена.

Вывод: требуется full-fidelity retranslation.

### `docs/spec.md`

Спецификация требует особенно строгого режима перевода, поскольку является нормативным документом.

Уже в начальной секции локальная версия не просто переводит upstream, а переформулирует и сокращает его. Кроме того, исходная EBNF notation в `go1.27.1` использует productions:

```text
Expression = Term { "|" Term } .
Term       = Factor { Factor } .
Factor     = production_name | token [ "…" token ] | Group | Option | Repetition .
```

В локальном файле эти non-terminal names были переименованы в другую grammar hierarchy. Для tutorial это могло бы быть допустимым объяснением, но для перевода Language Specification изменение нормативной grammar недопустимо.

До полного восстановления `docs/spec.md` нормативным источником остаётся:

`golang/go@go1.27.1:doc/go_spec.html`.

## 3. Metadata

В Go-разделе используется собственная схема frontmatter:

- `title`;
- `technology`;
- `version`;
- `upstream_repository`;
- `upstream_path`;
- `upstream_ref`;
- `translation_status`.

Она отличается по именам от глобального `_templates/translation-page.md`, но содержит необходимые данные для воспроизводимой синхронизации.

На текущем этапе схема сохраняется, чтобы не выполнять бессмысленную массовую миграцию 65 файлов. Она зафиксирована в `sync-rules.md` как Go-specific schema.

## 6. Definition of Done для одного документа

Страница может быть помечена `reviewed`, только если:

1. `upstream_repository`, `upstream_path`, `upstream_ref` разрешаются в существующий source;
2. сохранены все semantic sections upstream;
3. не потеряны paragraphs, warnings, notes, lists, tables и examples;
4. code blocks сохранены без смысловой модификации;
5. нормативные grammar/API identifiers не переименованы;
6. internal links либо переведены в существующий WikiLink, либо оставлены canonical upstream URL;
7. отсутствует summary, заменяющий исходный текст;
8. `translation_status` изменён на `reviewed` только после этой проверки.
